# クローン配布・移動・更新手順

## 配布するもの

この版は、ソースをクローンした側でランタイムと依存関係を自動取得する方式です。配布するリポジトリには `scripts/`、バックエンド、フロントエンド、両ロックファイル、起動スクリプト、`LICENSE`、`THIRD_PARTY_NOTICES.md` を含めます。実行用バイナリをGitに追加する必要はありません。

GitHubの `main` をクローンするか、ソースZIPを展開してください。どちらの場合も同じフォルダに起動スクリプトがあります。

Windowsは `AntiDupeImage.bat`、macOSは `bash AntiDupeImage.command` で起動します。通常権限で書き込めるフォルダへ配置してください。ブラウザー・OS標準のPowerShellまたはbash/curl/tarはOS側を使用します。GPUを使う場合のドライバーもOS側が必要です。

生成物の `.portable/`、`frontend/node_modules/`、`frontend/dist/`、`data/` は `.gitignore` で除外しています。第三者へ既存フォルダを渡す場合は、画像・DB・APIトークン・スキャン履歴・個人のパスを含めず、ソースのクローンを配布してください。

`portable/` にある旧Windowsバイナリ候補の組立は別の配布方式です。候補アーカイブの再配布条件は、その候補の文書で確認してください。

## 初回セットアップとオフライン利用

初回はGitHub（uv・Python）、nodejs.org、PyPI・npm registryへアクセスします。MLを指定した場合はPyTorchの配布元も使用します。uv・Node.jsは固定した公式SHA-256を照合してから展開し、Pythonは固定版をuvで取得します。Python依存は `uv.lock`、npm依存は `package-lock.json` に固定します。

初回の取得が済めば、基本機能は次のコマンドでオフライン起動できます。

```bat
AntiDupeImage.bat --offline
```

```bash
bash AntiDupeImage.command --offline
```

依存追加・ロック変更・異なるOS/CPUへの移動で未取得のファイルが必要な場合、オフライン構築は不足をエラーとして報告します。CLIPモデル重みはMLパッケージとは別で、最初にCLIPを使用する際に取得されます。完全オフラインでCLIPを使うには、そのモデルも先に取得しておく必要があります。

## フォルダを移動する

1. アプリを終了します。
2. 同じOS・CPUのPCへ、`.portable/` と `data/` を含むフォルダ全体をコピーします。
3. 移動先で通常の起動スクリプトを実行します。

リポジトリの位置変更を検知すると、パスを埋め込む仮想環境をローカルの保存済みキャッシュから再構築し、画面も再ビルドします。`--offline` でも同じ動作を使えます。コピーの際に隠しフォルダを省かないでください。異なるOS・CPUへ持ち運ぶ場合はソースと必要なデータを移し、ランタイムをそのOS用に取得してください。

DB内のスキャン元画像パスは自動で書き換えません。画像も別の場所へ移した場合は、移動先を再スキャンしてください。フォルダ全体をコピーする場合、既存データは同じ利用者の移行用です。

## 更新・復旧

同じフォルダのアプリ実行中・構築中は、二度目の起動をエラーとして拒否します。既存のコンソールを終了してから再試行してください。ロックはプロセス終了時に解放されるため、`instance.lock` が残っていても手動削除は不要です。

セットアップ状態は原子的に保存します。状態ファイルが破損した場合は再構築し、`data/` を保持します。任意ML構成を使用していた場合は `--ml` / `--cuda` を明示して再設定してください。

アプリを停止し、`data/` をバックアップしてからソースを更新します。

`data/antidupeimage.sqlite3` が破損・使用不能な場合、CLIは `Local database error` を表示して非ゼロで終了します。データフォルダ自体が書き込み不能な場合も同様にエラーで停止します。バックアップした `data/` を戻すか、破損したファイルを退避して再実行してください（退避したファイルを削除すると移動履歴などの既存データは失われます）。

```bash
git pull --ff-only
```

```bat
AntiDupeImage.bat --setup-only
```

```bash
bash AntiDupeImage.command --setup-only
```

ソース・ロック・ランタイム定義の変更は起動時にも検知します。構築に失敗した場合、完成状態の記録は更新せず、次回起動で再試行します。DBの移行は既存のトランザクション方式を使用します。旧版へ戻す場合は、旧版のコードと対応するバックアップDBを組み合わせてください。

既存の `.venv/` は手動開発用として保持します。ポータブル本番環境は `.portable/venv/` に独立して作成するため、旧仮想環境は自動削除しません。

## 検証

ソース候補の固定には `backend/tools/package_source_candidate.py --output <新規ZIP>` を使います。出力先は既存フォルダにし、候補ZIP・ファイル別SHA-256一覧・作業用チェック表を別々に管理してください。既存ZIPの上書きは拒否します。未コミット変更も現在のソースから取り込み、個人データ・キャッシュ・バックアップ・更新用チェック表は含めません。同じ入力でZIPを再作成し、ハッシュを照合できます。

`backend/tests/test_portable.py` はハッシュ不一致拒否、保存先、macOS側の版固定を確認します。実機用テストは空のソースコピーで初回取得し、日本語・空白の場所へ移動後、オフライン再構築、画面配信、未認証拒否、単回bootstrap、生成画像の重複スキャンを確認します。

Windowsのローカル環境で実行する例:

```powershell
$env:ADI_PORTABLE_SMOKE = '1'
.portable\dev-venv\Scripts\python.exe -m pytest backend/tests/test_portable.py -p no:cacheprovider
```

実機テストにはpytestとPillowを導入した開発環境を使用します。本番セットアップは開発用Pythonパッケージを導入しません。

Pythonロック依存の公開アドバイザリ確認はPython 3.11以降で `python backend/tools/audit_locked_dependencies.py` を実行します。通常はローカルPythonを指定してください。OSVへの通信が必要で、該当版は終了コード1、通信・応答不備は2になります。該当結果は実行経路と上流アドバイザリへ照合して判断します。CIではPython 3.12ジョブで実行します。E2Eは `UV_PROJECT_ENVIRONMENT` を明示すると、その開発用仮想環境を優先します。
